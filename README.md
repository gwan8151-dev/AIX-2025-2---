# 1. 주제 및 주제 선정 과정 (10/29-11/4)
### **1.1 주제 설명**

이번 프로젝트의 주제는 딥러닝 기반 객체 탐지 모델인 YOLO를 활용하여 생활 속에서 흔히 배출되는 금속캔, 종이, 유리병, 플라스틱을 이미지로 자동 분류하는 것이다. YOLO는 이미지 속 객체의 위치와 종류를 동시에 파악할 수 있는 객체 탐지 모델로, 빠른 처리 속도와 높은 정확도로 실시간 분류가 가능하다는 점에서 다양한 분야에서 활용되고 있다. 본 프로젝트에서는 쓰레기 이미지를 라벨링하여 학습 데이터를 만든 뒤, YOLO 모델을 학습시켜 네 가지 재활용품을 자동으로 분류하도록 구현할 것이다. 이를 통해 일상에서 촬영된 다양한 쓰레기 형태를 얼마나 정확하게 인식할 수 있는지 확인하고, 딥러닝 기반 객체 탐지 기술이 실제 분리배출 지원 도구로 활용될 수 있는 가능성을 확인해보고자 한다.

### **1.2 주제 선정 과정**

어린 아이들은 물론, 성인들도 분리배출을 하다 보면 이것이 플라스틱인지, 금속인지, 유리병인지 헷갈리는 경우가 많다. 딥러닝 수업을 들으면서 이미지 기반 객체 인식 모델인 YOLO를 접하게 되었고, 이를 활용하면 사람이 눈으로 구별하듯 카메라에 찍힌 사진만으로 쓰레기의 종류를 자동으로 판별할 수 있다는 점에서 흥미를 느꼈다. 만약 이러한 기술이 실제 생활에서 활용될 수 있다면, 어린 아이들 뿐만 아니라 쓰레기 분리배출을 할때 헷갈려하는 모든 사람들이 겪는 혼란을 줄일 수 있고 재활용 시스템 효율을 높이는 데도 기여할 수 있을 것이라고 생각했다. 이를 통해 도시 환경 문제를 해결하는 도구로서 의미가 있다고 생각하였다. 이러한 문제의식을 가지고 YOLO 모델을 활용하여 쓰레기를 분류하는 프로젝트를 선정하게 되었고, 금속캔·종이·유리병·플라스틱 등 일상에서 자주 볼 수 있는 폐기물을 이미지로 인식하고 자동으로 분류하는 실험을 진행해 보고자 한다.

# 2. YOLO 모델에 대해서

## 2.1 객체 탐지(Object Detection)란?

먼저 YOLO를 이해하기 위해 객체 탐지가 무엇인지 알아야 한다.

### 이미지 분류 vs 객체 탐지

**이미지 분류(Image Classification)**

- "이 사진은 무엇인가?" → "개 사진입니다"
- 전체 이미지를 보고 하나의 정답만 제시한다.

**객체 탐지(Object Detection)**

- "이 사진에 무엇이 어디에 있나?" → "개가 왼쪽에, 고양이가 오른쪽에 있습니다"
- 여러 물체의 **위치**와 **종류**를 동시에 찾아낸다.

### 객체 탐지의 두 가지 과제

1. **Classification (분류)**: 이게 무엇인지 판단한다.
2. **Localization (위치 찾기)**: 어디에 있는지 박스로 표시한다.

YOLO는 이 두 가지를 **동시에** 수행하는 모델이다.

## 2.2 YOLO란?
YOLO(You Only look Once)는 2016년에 처음 발표된 실시간 객체 탐지 알고리즘이다.

### 왜 YOLO라는 이름일까?

기존의 객체 탐지 방법들은 이미지를 여러 번 반복해서 분석했다. 예를 들어:

- 1단계: 물체가 있을 만한 영역 찾기
- 2단계: 각 영역을 다시 분석해서 물체 분류하기
- 3단계: 결과 정제하기

하지만 YOLO는 이름 그대로 **"단 한 번만 보고(You Only Look Once)"** 모든 작업을 끝낸다.

### 쉬운 비유로 이해하기

**기존 방식 (R-CNN 계열)**

- 선생님이 교실을 둘러보며 한 명씩 "너는 학생이니?" 확인한다.
- 느리지만 꼼꼼하다.
- 한 장의 사진을 분석하는데 수십 초 소요한다.

**YOLO 방식**

- 선생님이 교실을 한 번 쭉 보고 "1번 자리 학생, 3번 자리 선생님, 5번 자리 학생" 한 번에 파악한다.
- 빠르지만 가끔 놓칠 수 있다.
- 한 장의 사진을 분석하는데 0.03초 소요한다. (초당 30장 이상)

### YOLO의 혁신적인 점

**속도**: 실시간(30 FPS 이상)으로 동작 가능하다.

- 자율주행차, CCTV 모니터링 등에 활용한다.
- 비디오에서도 즉시 물체 추적 가능하다.

**정확도**: 빠르면서도 꽤 정확하다.

- 초기 버전은 정확도가 낮았지만 계속 개선하고있다.
- 현재(v8)는 속도와 정확도 모두 우수하다.

**간단함**: 하나의 신경망으로 모든 처리한다.

- 복잡한 파이프라인이 없다.
- 학습과 사용이 간단하다.

## 2.3 YOLO의 작동 원리

### 1단계: 이미지를 그리드(Grid)로 나누기

1. 입력 이미지를 고정된 크기(예: 640×640)로 리사이즈한다.
2. 이 이미지를 (S times S) 개의 **격자 셀(Grid cell)** 로 나눈다.
    - 예: 13×13, 19×19 등

```
┌─┬─┬─┬─┬─┬─┬─┐
├─┼─┼─┼─┼─┼─┼─┤
├─┼─┼─┼─┼─┼─┼─┤   ← 격자 예시
├─┼─┼─┼─┼─┼─┼─┤
├─┼─┼─┼─┼─┼─┼─┤
├─┼─┼─┼─┼─┼─┼─┤
└─┴─┴─┴─┴─┴─┴─┘

```

각 셀은

> “내 영역 안에 중심이 들어오는 재활용 쓰레기(금속캔, 종이, 유리병, 플라스틱) 가 있다면, 그 객체는 내가 책임지고 예측한다”
> 

라는 역할을 맡는다.

이 덕분에 이미지 전체를 한 번에 보면서도, 위치 정보를 격자 단위로 구조화할 수 있다.

---

### 2단계: 각 셀에서 바운딩 박스와 점수 예측

YOLO의 신경망은 특징 맵을 이용해,

**각 그리드 셀마다 여러 개의 바운딩 박스 후보와 그 박스에 대한 정보를 동시에 예측**한다.

각 바운딩 박스는 다음 값을 가진다.

1. **좌표와 크기 ((x, y, w, h))**
    - (x, y): 박스 중심 좌표 (0~1로 정규화)
    - (w, h): 박스의 너비와 높이 (0~1로 정규화)
    - 예: 금속캔의 중심이 이미지 가운데에 있으면 ((x, y) ≈ (0.5, 0.5))
2. **객체성(Objectness, 신뢰도 점수)**
    - 이 박스 안에 “의미 있는 재활용 쓰레기”가 있을 확률
    - 예: 0.9라면 “이 박스 안에 캔/종이/유리병/플라스틱 중 하나가 있을 가능성이 90%”라는 뜻
3. **클래스 확률(Class probabilities)**
    - 이 박스 안의 물체가 네 가지 클래스 중 무엇일지에 대한 확률
    - 예:
        - metal_can 80%
        - paper 10%
        - glass_bottle 5%
        - plastic 5%

이렇게 해서 YOLO는

> “이 위치에 이런 크기의 박스가 있고, 그 안의 물체는 metal_can일 가능성이 가장 크다”
> 

와 같은 정보를 한 번에 출력한다.

---

### 3단계: 최종 점수 계산과 후보 박스 생성

실제로는 각 박스에 대해

> 최종 점수 = 객체성(Objectness) × 해당 재활용 클래스 확률
> 

을 곱해서 사용한다.

- 예시
    - objectness = 0.9, metal_can 확률 = 0.8 → metal_can 점수 = 0.72
    - objectness = 0.9, glass_bottle 확률 = 0.3 → glass_bottle 점수 = 0.27

이렇게 계산된 수많은 후보 박스 중에서

기본적으로 **conf = 0.25** 같은 임계값보다 낮은 박스는 모두 제거한다.

우리 프로젝트에서는 데이터가 적기 때문에,

학습 초반에는 `conf=0.05`처럼 더 낮은 값으로 설정해

“모델이 종이팩, 플라스틱 병, 유리컵 등을 어디서 헷갈리는지”를 분석하기도 했다.

---

### 4단계: NMS(Non‑Maximum Suppression)로 중복 박스 제거

임계값을 적용한 뒤에도,

하나의 캔이나 유리병 주위에 여러 박스가 겹쳐 있는 경우가 많다.

이를 정리하기 위해 **NMS(비최대 억제)** 알고리즘을 사용한다.

1. 같은 클래스(예: metal_can)에 대해 점수가 가장 높은 박스를 하나 고른다.
2. 이 박스와 **IoU(Intersection over Union)** 가 높은,
    
    즉 거의 같은 물체(같은 캔)를 가리키는 다른 박스들을 찾는다.
    
3. IoU가 기준(예: 0.5) 이상이면 중복으로 보고 제거한다.
4. 남은 박스들에 대해 이 과정을 반복한다.

이 과정을 거치면 최종적으로는

- 캔 하나당 metal_can 박스 1개,
- 유리병 하나당 glass_bottle 박스 1개,
- 종이·플라스틱도 각각 1개씩

만 남게 되고,

이미지 위에는 `metal_can 0.97`, `plastic 0.85` 와 같은 라벨과 점수가 표시된다.

---

### 5단계: 엔드투엔드 구조와 전역적 추론

마지막으로, YOLO의 구조적 특징을 재활용 문제 관점에서 정리하면 다음과 같다.

1. **엔드투엔드(End‑to‑End) 단일 네트워크**
    - “쓰레기 후보 영역 찾기 → 별도 분류기 돌리기”처럼 여러 단계를 나누지 않는다.
    - 원본 이미지 → CNN → 그리드별 박스 + 클래스 점수 → NMS
        
        전 과정을 한 네트워크가 한 번에 학습한다.
        
    - 덕분에 실시간 카메라로 촬영한 분리배출 장면도 빠르게 처리할 수 있다.
2. **전역적 추론(Global Reasoning)**
    - 이미지 전체를 한 번에 보기 때문에,
        
        쓰레기통 위치, 바닥/테이블 배경 등 **주변 맥락 정보**를 함께 활용할 수 있다.
        
    - 예를 들어, 분리수거함 주변에 모여 있는 캔·병·종이팩이 섞여 있어도
        
        전체 장면 정보를 이용해 비교적 안정적으로 인식한다.

## **2.4 YOLO의 발전 과정(요약)**

YOLO는 2016년 이후 속도와 정확도를 동시에 개선해 오면서 여러 버전으로 발전했다.

- **YOLOv1 (2016)**
    - 최초의 실시간 객체 탐지 모델
    - 빠르지만 작은 물체에는 약함
- **YOLOv2–v3 (2017–2018)**
    - Anchor box, 멀티 스케일 예측 도입
    - 작은 물체 탐지와 전체 정확도 크게 향상
- **YOLOv4–v5 (2020)**
    - 최신 학습 기법과 PyTorch 구현으로 성능·편의성 개선
    - n, s, m, l, x 등 다양한 크기 모델 제공
- **YOLOv8 (2023, 최신)**
    - Ultralytics에서 공개한 Anchor‑free 구조
    - 향상된 손실 함수와 아키텍처로 현재 가장 널리 쓰이는 강력한 버전

| **모델** | **특징** | **mAP** |
| --- | --- | --- |
| YOLOv8n | 가장 가볍고 빠름 | 37.3 |
| YOLOv8s | 속도와 정확도 균형 | 44.9 |
| YOLOv8m | 중간 크기 | 50.2 |
| YOLOv8l/x | 높은 정확도 | 52.9-53.9 |

## 2.5 YOLO의 장단점

### 장점

**1. 압도적인 속도**

- **실시간 처리**: 초당 30-100 프레임 이상이다.
- **즉각적인 피드백**: 비디오 스트림에서도 사용 가능하다.
- **응용 분야**: 자율주행, 드론, 실시간 모니터링

**2. 한 번에 전체 이미지 분석**

- **전역적 맥락 이해**: 배경 정보도 활용가능하다.
- **False Positive 감소**: 배경을 물체로 오인하는 경우가 적다.
- **관계 이해**: 물체 간의 관계도 파악가능하다.

**3. 일반화 성능 우수**

- **새로운 이미지에 강함**: 다양한 환경에서 작동한다.
- **도메인 전이**: 한 분야에서 학습한 모델을 다른 분야에 적용 가능하다.

**4. 단순한 파이프라인**

- **하나의 네트워크**: 복잡한 여러 단계 불필요하다.
- **학습 간단**: End-to-End 학습
- **배포 쉬움**: 모델 하나만 있으면 된다.

**5. 다양한 크기 물체 탐지**

- **멀티스케일**: 작은 물체부터 큰 물체까지 가능하다.
- **밀집된 물체**: 여러 물체가 모여있어도 탐지 가능하다.

**6. 활발한 커뮤니티와 생태계**

- **풍부한 자료**: 튜토리얼, 예제 코드가 많다.
- **지속적인 발전**: 새로운 버전이 계속 출시된다.
- **다양한 구현**: PyTorch, TensorFlow 등

### 단점

**1. 작은 물체 탐지의 어려움**

- **이유**: 격자 크기의 제약이 있다.
- **영향**: 멀리 있는 물체나 작은 물체 놓칠 수 있다.
- **예시**: 드론으로 찍은 고도에서 사람 탐지, 작은 나사나 부품

**2. 밀집된 작은 물체**

- **한계**: 한 격자에 여러 물체가 있으면 일부만 탐지된다.
- **예시**: 새 떼, 작은 물체가 여러 개 모여있는 경우

**3. 정확한 위치 지정의 제약**

- **이유**: 격자 기반 예측
- **영향**: 바운딩 박스가 완벽히 정확하지 않을 수 있다.
- **대안**: Instance Segmentation 모델 (Mask R-CNN 등)

**4. 학습 데이터 의존성**

- **필요**: 각 클래스별로 충분한 학습 데이터 필요하다.
- **문제**: 드문 케이스는 학습 어렵다.
- **해결**: 데이터 증강, 전이 학습 활용

**5. 하드웨어 요구사항**

### 문제 원인일 가능성이 있는 요인들

**1) 라벨 불일치 문제**

YOLO는 **클래스 번호가 0~N-1 순서로 정확히 매칭**돼 있어야 한다. 단 classes.txt 순서와 각 라벨의 .txt 안의 클래스 번호가 매칭 되지 않은 데이터가 일부 있는 것으로 확인되었다.

이는 수정 후 다시 학습을 진행해 볼 예정이다.

---

**2) 적은 학습 데이터의 수**

현재 클래스 당 40장 정도의 데이터로 학습을 진행하였다.

이러한 경우 loss는 줄지만 model이 아무것도 확신하지 못하는 상태가 되어 confidence가 0.25를 넘기지 못해 박스가 아예 출력되지 않았을 가능성이 있다.

---

**3) threshold(신뢰도 기준)이 너무 높음 (2번과 비슷한 맥락)**

YOLO predict 기본 threshold는 conf=0.25이다.

학습 데이터가 적으면 모든 예측이 conf < 0.25로 떨어지므로 박스가 생성되지 않았을 가능성이다.

이를 검증하려면 

```
yolo predict model=best.pt source=images/ conf=0.05
```

처럼 threshold를 낮춰보면 된다는 것을 조사를 통해 알게 되었다. 추후 여러 원인 가능성에 대한 분석 후 내용 추가 예정이다.

---

**4) 라벨 좌표 형식 오탈자/스케일 문제**

YOLO 라벨에서 좌표는 반드시 {class x_center y_center width height } (모두 0~1 범위) 와 같은 형태여야 한다.

만약 width/height이 1을 넘기거나 음수이거나, x_center,y_center이 0~1 벗어나는 데이터가 있을 경우 학습과 예측에 지장을 줄 수 있다. 이는 전처리 코드를 추가하는 것으로 해결할 수 있다.

### **5.3 데이터 라벨링**

 객체 탐지 모델 학습을 위해 Github 오픈소스 라벨링 도구인 LabelImg를 활용하여 이미지 데이터셋에 대한 Bounding Box 기반 객체 라벨링 작업을 수행하였다. LabelImg는 Python 기반의 GUI 라벨링 도구로, YOLO 포맷(.txt)과 Pascal VOC 포맷(.xml) 모두를 지원하며, 가벼운 인터페이스와 직관적인 조작을 통해 효율적인 라벨링 작업이 가능하다는 장점을 가진다.

 먼저 학습에 사용할 원본 이미지를 프로그램에 불러온 후, 마우스를 이용하여 탐지 대상 객체 영역을 사각형(Bounding Box)으로 지정하였다. 이후 해당 객체가 속하는 클래스명을 선택하여 저장하면 YOLO 학습에 필요한 텍스트 형식의 라벨 파일이 자동으로 생성된다. 생성된 라벨 파일은 이미지와 동일한 파일명을 가지며, 객체의 중심 좌표(x, y), 폭(w), 높이(h)가 이미지 크기로 정규화되어 기록된다. 이를 통해 모델이 객체의 정확한 위치 정보를 학습할 수 있도록 데이터를 구조적으로 구성하였다.

```jsx
  - metal_can
  - paper

```

### **5.5 학습실행**

```
yolo detect train [model=yolov8n.pt](http://model=yolov8n.pt/) data=data.yaml epochs=25 imgsz=640 device=cpu
```

- 학습 명령에는 사용할 사전 학습 모델([yolov8n.pt](http://yolov8n.pt/)), 데이터 구조를 정의한 data.yaml, 학습 반복 횟수를 지정하는 epochs(25), 입력 이미지 크기(imgsz), 그리고 CPU·GPU 중 어떤 장치를 사용할지(device) 등이 포함된다. 사용자가 명령어를 실행하면 YOLO는 train 폴더의 이미지와 라벨을 읽어 모델을 학습시키고, val 데이터로 성능을 검증하여 최종적으로 가장 성능이 좋은 모델을 best.pt로 저장한다.
